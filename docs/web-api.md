# API и подключение ML

## API для жюри

Все запросы к `/api/v1/` требуют заголовок `X-API-Key`. Ключ — переменная окружения `FORTE_API_KEY`; скрипт запуска создаёт случайный ключ, если она не задана. Ни UI, ни health endpoint ключ не раскрывают.

`POST /api/v1/analyze` принимает multipart-поле `file`. Допускаются `.mov`/`.mp4` (регистр не важен), максимум 100 МиБ. Расширение не доказывает корректность контейнера: ошибки декодирования становятся `failed`. Пустой файл, неверное расширение и превышение лимита отклоняются. Без настроенного анализатора возвращается 503; при заполненной очереди — 429.

Успешное принятие возвращает `job_id` и `status: "processing"`. Затем опрашивайте `GET /api/v1/jobs/{job_id}`. Завершённый результат:

```json
{
  "job_id": "opaque-identifier",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Тип, определённый анализатором команды",
      "timecode_sec": 22.0,
      "description": "Наблюдаемое действие; название и раздел применимого правила.",
      "evidence_frames": [
        {"timestamp_sec": 22.0, "image_base64": "<raw JPEG base64>"}
      ]
    }
  ]
}
```

Для отрицательного результата: `verdict: "no_violation"`, `violations: []`. Для технической ошибки: `status: "failed"` и `error`, без ложного отрицательного вердикта. Сервис может добавлять `filename`, `model_name`, `duration_sec`, `elapsed_sec`, `limitations` и `rule` у события. На эти дополнительные поля проверяющий клиент может не опираться.

Кадры передаются как чистая строка base64 JPEG, без префикса `data:`. У каждого кадра собственный фактический таймкод. Окончательное извлечение выполняется сервером из присланного файла; встроенные в результат плагина изображения не принимаются как доказательства.

## Интерфейс команды ML

Доступная Python-функция `module:function` принимает **один `pathlib.Path` к локальному видео** и синхронно возвращает словарь:

```python
def analyze_video(video_path):
    # Загрузить собственную локальную модель и выполнить анализ.
    return {
        "verdict": "violation",  # либо no_violation
        "violations": [{
            "type": actual_event_type,
            "timecode_sec": actual_event_second,
            "description": observed_action_and_reason,
            "rule": {  # необязательно в протоколе, обязательно для обоснования кейса
                "title": verified_document_title,
                "url": verified_public_http_url,
                "clause": verified_section,  # если раздел неизвестен, поле опустить
            },
        }],
        "model_name": "Имя и версия модели команды",
        "limitations": [],
    }
```

Показанный фрагмент — описание контракта, не готовая реализация и не основание автоматически назначать нарушения. Рабочая заготовка `examples/custom_analyzer.py` выбрасывает `NotImplementedError`, пока ML-команда не добавит реальный анализ.

Функция должна:

- определить события только по видимым действиям; не выводить невидимые банковские операции;
- вернуть все обнаруженные события и конечные числовые таймкоды внутри длительности видео;
- возвращать пустой список при `no_violation` и непустой при `violation`;
- указывать проверенный документ для каждого правового основания; отсутствие источника отображается как ограничение;
- выполнять анализ локально без внешних AI API; не использовать и не передавать видео жюри для обучения.

Указывайте модуль через `FORTE_ANALYZER`, перезапускайте сервис после изменения конфигурации. Если задан и callable, и bundle, приоритет у callable. Готовность в config означает наличие синтаксически корректной конфигурации: основной веб-процесс не импортирует модуль модели. Импорт, загрузка весов и анализ исполняются в отдельном процессе с дедлайном; ошибка импорта или загрузки даёт `failed`. Учитывайте время загрузки. Это MVP с одним последовательным worker, не распределённый ML-сервер.

## API интерфейса

`GET /api/ui/config` создаёт HttpOnly-сессию и возвращает готовность анализатора и лимит загрузки. `POST /api/ui/analyze` и `GET /api/ui/jobs/{id}` используют эту сессию. `GET /api/ui/jobs/{id}/video` отдаёт владельцу задания только MP4-копию с размытием обнаруженных лиц и поддерживает range-запросы видеоплеера. Изменяющие запросы требуют Origin своего сервиса; при reverse proxy настройте правильный публичный протокол.

UI-пути не требуют и не раскрывают ключ жюри. Сессия не является аккаунтом: история разных браузеров не объединяется.

### Предпросмотр с размытием лиц

`POST /api/ui/previews` принимает один multipart-файл `file` (MOV/MP4, до установленного лимита), требует сессию и свой Origin, работает независимо от готовности ML-анализатора. После локальной подготовки возвращает HTTP 200:

```json
{"preview_id":"opaque-identifier","video_url":"/api/ui/previews/opaque-identifier/video","duration_sec":19.8,"privacy":{"method":"local_yunet","frames_processed":592,"face_detections":342,"limitation":"Автоматический детектор может пропускать лица."}}
```

Числа приведены как пример. `face_detections` — число найденных рамок суммарно по кадрам, не количество людей. Обработка ограничена 120 секундами в отдельном процессе. Выход — H264 MP4 без аудио; временные метки сохраняются относительно первого кадра. Исходный временный файл удаляется и при успехе, и при ошибке. Копии приватны, доступны только владельцу сессии, ограничены сроком хранения и числом записей из настроек сервиса. При ошибке возвращается 503, исходник не подставляется вместо защищённой копии.

Фронтенд сохраняет выбранный оригинал для отдельного запроса к модели; распознавание кассовых действий не выполняется на размытой копии. JPEG-доказательства и кадры демо также скрывают обнаруженные лица. Юридические описания и таймкоды от этого не меняются. YuNet работает локально, не выполняет идентификацию личности и может пропускать лица в сложных ракурсах.

Демо подготавливается владельцем сервера из предоставленного обучающего видео командой `scripts/create-demo.py --video ... --timecode ... --label violation`. GET `/api/ui/demo` отдаёт пример с исходной разметкой, GET `/api/ui/demo/video` — браузерную MP4-копию. Оба маршрута требуют UI-сессию; данные лежат в `FORTE_DATA_DIR/demo/`, вне Git и публичной папки static. Поле `demo_available` в UI config сообщает, подготовлен ли пример. Модель не вызывается, записи в очередь заданий не создаются; `/api/v1/` продолжает обрабатывать только реальные запросы к модели.
