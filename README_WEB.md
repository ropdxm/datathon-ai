# Forte — кассовый контроль

MVP веб-сервиса для хакатона: загрузка видео, асинхронная проверка, карточки событий с таймкодами и JPEG-кадрами, защищённый API для жюри. Интерфейс на русском, работает без внешних шрифтов и JavaScript-сервисов.

## Запустить

Нужен Python 3.11 или новее. Клонируйте репозиторий:

```bash
git clone https://github.com/ropdxm/datathon-ai.git
cd datathon-ai
```

Из папки проекта:

```bash
./scripts/run-web.sh
```

Открыть **http://localhost:8000**. Первый запуск создаёт `.venv-web`, устанавливает веб-зависимости и генерирует API-ключ в `.forte-runtime/jury-api-key`. Ключ не выводится в логи и не попадает в браузер.

Если `python3` старее 3.11, укажите подходящий интерпретатор:

```bash
PYTHON_BIN=/absolute/path/to/python3.12 ./scripts/run-web.sh
```

**Веса пока не подключены.** В этом состоянии можно выбрать и просмотреть видео, открыть подготовленный на сервере пример из датасета; запуск настоящего анализа недоступен. API возвращает 503 с объяснением. В демо событие берётся из исходной разметки, модель не запускается.

## Подготовить демо на предоставленном видео

Укажите исходный ролик из обучающего датасета и время из его разметки. Например, `Х-26.mov` размечен как «нарушение» на 9-й секунде; видно, как сотрудница оставляет банкноты на столе и выходит:

```bash
.venv-web/bin/python scripts/create-demo.py \
  --video /absolute/path/to/Х-26.mov --timecode 9 --label violation \
  --evidence-times 9 16 19 \
  --title "Наличные оставлены на столе при уходе сотрудницы" \
  --description "На 8–9 с сотрудница кладёт пачку банкнот на стол. Затем выходит из комнаты; банкноты остаются на столе до конца записи."
```

Для подготовки нужен установленный `ffmpeg`. Скрипт сохраняет браузерную MP4-копию и JPEG-кадры из оригинала в `.forte-runtime/demo/` (либо в `FORTE_DATA_DIR/demo/`). Затем нажмите «Демо интерфейса» в интерфейсе. По умолчанию новые серверы не содержат роликов: их нужно подготовить этой командой локально. Клип, кадры и разметка в Git и архив исходников не включаются.

Демо показывает заданную метку и таймкод, не результаты модели. Конкретный тип нарушения и норматив не подставляются, если их нет в исходной разметке. Для нормального видео используйте `--label no_violation`.

## Подключить результат тиммейтов

Предпочтительный вариант — Python-функция, которая возвращает отдельные события с типом, временем, описанием и проверенным нормативным основанием. Контракт и заготовка: `examples/custom_analyzer.py` и [docs/web-api.md](docs/web-api.md).

Создайте `.env` из `.env.example` и задайте:

```bash
FORTE_ANALYZER="my_team.analyzer:analyze_video"
FORTE_DEVICE="auto"
```

Модуль `my_team` должен быть доступен Python из папки проекта. Установите зависимости модели в `.venv-web`, затем перезапустите сервис. Загруженные веса и код должны выполнять анализ локально, без облачных AI API. `FORTE_ANALYZER` задаётся владельцем сервера, а не пользователем сайта.

Для офлайн-бандла, выгруженного нашими Colab-ноутбуками, распакуйте архив и укажите папку, содержащую `config.json`, `head.pt` и `encoder/`:

```bash
FORTE_MODEL_BUNDLE="/absolute/path/to/bundle"
FORTE_DEVICE="auto"
```

Установите совместимые с бандлом зависимости PyTorch/torchvision в `.venv-web`; используйте `requirements.txt` внутри папки `inference_bundle` из выгрузки как перечень проверенных версий и подберите сборку PyTorch под сервер. На Mac CUDA-сборка не подходит. Бандл и зависимости загружаются до проверки; во время анализа сеть не нужна.

**Ограничение Colab-бейзлайна:** бинарный классификатор возвращает оценку видео и одно приблизительное подозрительное окно. Он не определяет конкретный состав нарушения, полный список событий или правовое основание. MVP показывает эти ограничения явно, не придумывает норматив и не заменяет отсутствующий анализ демонстрационными карточками. Для полного соответствия кейсу команда должна передать доработанный анализатор событий.

## Тиммейту, который добавляет анализатор

1. Получите актуальную ветку `main`. Добавьте модуль модели, например `team_ml/analyzer.py`, с синхронной функцией `analyze_video(video_path)`. Контракт результата описан в `docs/web-api.md`, заготовка — в `examples/custom_analyzer.py`.
2. Добавьте отдельный файл зависимостей модели и короткую инструкцию: откуда получить веса, как подготовить входные кадры и как запустить проверку нового видео.
3. Укажите локально в `.env` значение `FORTE_ANALYZER="team_ml.analyzer:analyze_video"`, установите зависимости в `.venv-web` и перезапустите веб. `.env` и API-ключ в Git не добавляются.
4. Проверьте настоящий `.mov` через UI и `POST /api/v1/analyze`. Положительный результат должен содержать отдельные события; отрицательный — пустой список `violations`. Ошибку загрузки модели нельзя превращать в «нарушений нет».
5. Коммитьте код, зависимости и инструкции. Веса храните отдельно (например, локально в игнорируемой папке `models/`); исходные видео, разметка и runtime-данные в этот репозиторий не входят.

При использовании нашего готового Colab-бандла отдельный модуль анализатора не обязателен: достаточно `FORTE_MODEL_BUNDLE` и совместимых зависимостей. Ограничения бинарной модели сохраняются.

## Что реализовано

- `.mov` и `.mp4` до 100 МиБ: выбор файла, перетаскивание, реальный прогресс загрузки, просмотр и обработка ошибок.
- Фоновая очередь, SQLite, состояния `processing` / `done` / `failed`, предельное время 300 секунд с учётом очереди. Зависший процесс анализа завершается; техническая ошибка не становится `no_violation`.
- Несколько событий: описание, таймкод, 1–3 кадра из оригинального видео с размытием обнаруженных лиц, переход к моменту, просмотр кадра и сохранение JSON.
- API `POST /api/v1/analyze`, `GET /api/v1/jobs/{job_id}` с `X-API-Key` и документация `/docs`.
- Отдельные сессии интерфейса: API-ключ жюри не отправляется frontend, чужие задания и исходные видео недоступны через UI.
- Локальное размытие лиц: YuNet/OpenCV создаёт отдельную MP4-копию для просмотра и скрывает обнаруженные лица в JPEG-кадрах. Модель анализа получает исходное видео без изменений. Детектор и веса включены в проект; при обработке внешние API не используются.

После выбора файла интерфейс сначала готовит защищённый предпросмотр (до 120 секунд). Подготовка работает и без подключённой модели анализа. При ошибке исходное видео не показывается; подготовку можно повторить. Видео и кадры демо проходят то же скрытие лиц.

YuNet определяет расположение лиц, не устанавливая личность. Он может пропускать маленькие, перекрытые лица и сложные ракурсы, поэтому это автоматическое скрытие обнаруженных лиц, а не гарантия полной анонимизации. Лицензия MIT и источник весов находятся в `webapp/assets/`.

## Проверка API

Прочитайте локальный ключ и передайте его только жюри. Пример загрузки:

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H "X-API-Key: YOUR_PRIVATE_KEY" \
  -F "file=@/absolute/path/to/video.mov"

curl http://localhost:8000/api/v1/jobs/JOB_ID \
  -H "X-API-Key: YOUR_PRIVATE_KEY"
```

Без настоящего анализатора POST завершится 503. После подключения модели он возвращает `job_id`; результат нужно опрашивать через GET. Неправильный или отсутствующий ключ отклоняется независимо от готовности модели.

## Перед сдачей

1. Подключить настоящую модель и проверить типы событий, таймкоды, кадры и нормативы на отложенных видео.
2. Проверить полный путь через UI и через API на реальном `.mov`, включая отрицательный результат и ошибку обработки. Измерить время, в том числе для двух заявок подряд: очередь входит в лимит пяти минут.
3. Запустить сервис на выбранном сервере с публичным HTTPS URL. Один процесс Uvicorn и один worker; для обратного прокси разрешайте forwarded-заголовки только от его адреса. Локальный URL сам по себе не является публичным размещением.
4. Передать жюри адрес интерфейса, адрес API, API-ключ, инструкцию и ограничения поддерживаемых типов. Держать сервер включённым на время проверки.

Адрес/порт регулируются `HOST`/`PORT`. Данные и ключ находятся в `FORTE_DATA_DIR` (по умолчанию `.forte-runtime`); каталог нельзя публиковать как статические файлы. Не запускайте второй процесс сервиса с той же базой. После перезапуска незавершённые задания помечаются как ошибочные.

## Проверки и передача проекта

```bash
.venv-web/bin/python -m pip install pytest httpx
.venv-web/bin/python -m pytest tests/web -q
node --check webapp/static/app.js
./scripts/package-web.sh
```

Команда упаковки создаёт локальный архив `outputs/forte-web-mvp.zip` с исходниками и инструкциями, без ключей, видео банка, runtime-базы и весов. Каталог `outputs/` не хранится в Git. Четыре обучающих Colab-ноутбука передаются отдельно и в этот репозиторий веб-сервиса не включены.
